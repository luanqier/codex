# 执行型接入路线图

这份路线图的目标不是让系统更复杂，而是给 AI-Brain 增加“手脚”，让它逐步替用户做收集、筛选、整理、草拟、排程和复盘。

## 当前痛点

- 群消息、课程、视频、课件、资料同时涌入，注意力被切碎。
- 很多内容需要重复处理：复制、命名、归类、摘要、提炼选题、写脚本、做课件大纲。
- 用户真正需要亲自做的是判断、表达、录制、确认，而不是反复搬运信息。

## 总体思路

```text
外部输入
  -> 统一收集入口
  -> AI 初筛
  -> Skill 执行
  -> 用户确认
  -> 产出或归档
```

## 第一批要接入的能力

| 能力 | 解决什么 | 推荐方式 | 优先级 |
| --- | --- | --- | --- |
| 一键收集入口 | 不再到处复制资料 | Obsidian Web Clipper / n8n Webhook / 手动 Inbox | 高 |
| 群消息提炼 | 从群里找选题、机会和行动项 | 复制文本或 OCR 后交给群消息提炼 Skill | 高 |
| 课程消化 | 不再被课程数量压垮 | 课程目录筛选 + 转写摘要 + 章节优先级 | 高 |
| 视频课件流水线 | 把素材变成脚本和课件 | 视频课件生产流水线 Skill | 高 |
| 文件夹监听 | 新文件自动登记 | n8n 自托管监听资料文件夹 | 中 |
| 每日任务指挥台 | 每天只抓最重要的事 | Codex 每日触发或手动口令 | 高 |
| 每周自动复盘 | 找出重复劳动和自动化机会 | Codex Automation | 中 |

## 建议接入顺序

### 第 1 步：统一输入入口

先把所有内容统一送到 `00_Inbox_碎片收集/今日收集.md`。

可用入口：

- 手动复制到 Inbox
- 浏览器剪藏网页和课程页面
- 手机/电脑快捷入口发送到 n8n Webhook
- 文件路径登记到 Inbox

### 第 2 步：新增执行型 Skill

已新增：

- 群消息提炼 Skill
- 课程消化 Skill
- 视频课件生产流水线 Skill
- 每日任务指挥台 Skill

它们的关系：

```text
群消息/课程/资料
  -> 提炼成素材和选题
  -> 进入视频课件生产流水线
  -> 每日任务指挥台决定今天做什么
```

### 第 3 步：先半自动运行 7 天

每天只运行一次：

```text
启动每日任务指挥台。读取今天的 Inbox、课程、群消息和视频课件待办，帮我决定今天最该做什么，哪些先交给 AI 处理。
```

### 第 4 步：接入自动化

满足下面条件后再自动化：

- 手动跑过 3 次以上
- 输出格式稳定
- 用户确实觉得省力
- 不涉及对外发送或重要删除

优先自动化：

1. 每日任务指挥台草稿
2. 群消息摘要草稿
3. 课程目录筛选
4. 视频脚本初稿
5. 新文件登记到 Inbox

## 不建议马上做

- 不建议一开始自动读取和回复私密群聊。
- 不建议一开始自动删除、归档或改写重要笔记。
- 不建议同时接太多外部平台。
- 不建议追求全自动生产视频，先让 AI 负责脚本、大纲、素材表和归档。

## 本周最小实验

连续 3 天，每天只做：

1. 把当天群消息、课程、资料、视频想法丢进 Inbox。
2. 启动每日任务指挥台。
3. 让 AI 先处理 1 个群消息提炼或课程消化任务。
4. 从 AI 输出里选 1 个视频/课件产出推进。

如果 3 天后明显省力，再把“每日任务指挥台”接入 Codex Automation。
