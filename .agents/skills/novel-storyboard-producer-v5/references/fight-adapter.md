# 打斗模块适配层

本适配层把 `vendor/fight-prompt-director/` 限定为 V5 的条件性专业子模块。它增强动作可读性，不接管小说改编、Segment 规划、资产管理、图片生产、QA 或封包。

上游来源：`irenerachel/fight-prompt-director`，vendored 版本提交 `fee4387`。vendored 目录保持上游受版本控制文件原样，不在其中写 V5 专属规则。

## 何时启用

只对满足至少一项的目标 Segment 启用：

- 存在双方或多方的攻击、防守、追逐、争夺、逃脱或压制；
- 存在需要明确接触、格挡、落空、反制、受力或位移结果的动作；
- 存在武器、投射物、法术、能量或大型生物的连续攻防；
- 动作失败的主要风险是站位、距离、轴线、资源或镜头连续性不清。

只有奔跑、飞行、起身、转身、拿取物品或情绪性肢体动作，而没有攻防因果时，仍按核心流程处理，不加载本模块。

## 先锁定不可变输入

在设计动作前，从原文、项目设定、生产索引和目标 Segment 锁定以下合同：

| 锁定项 | 处理规则 |
|---|---|
| 剧情与目的 | 不改变事件顺序、冲突原因、动机、知识状态、关键结果和章节钩子 |
| 胜负与退出状态 | 不交换胜负，不新增击败、死亡、受伤、逃脱、救援、投降或后果 |
| 对白 | 原句及说话人保持不变；是否压缩只由核心 V4 流程决定 |
| 人物能力 | 不新增境界、术法、技能、体能、反应速度、武器、弹药或能量来源 |
| 时间结构 | 不增删 Segment，不改变任一 Segment 时长或章节总时长 |
| 输出结构 | 保留声明行、段级基线、镜号及时长，以及每镜六字段 |
| 连续资产 | 沿用已批准脸、服装、场景、道具、武器、光线和版本 |

若这些输入不足以唯一确定具体动作，选择不改变结果的最小细化；缺口会实质改变剧情或能力时，按核心流程追问或报告阻断，不让打斗模块补写设定。

## 允许的动作设计

只在合同内明确：

1. 谁发起动作，指向何处，以及使用既有身体、武器或能力的方式。
2. 接触、格挡或落空的可见结果，以及对方的即时回应。
3. 攻防前后的左右位置、朝向、距离、高度、重心、速度与下一拍接口。
4. 接触点、受力方向、位移和环境反馈；避免图形化伤害描写，并服从核心安全规则。
5. 唯一武器的持握手、角度和状态，以及既有弹药/能量的取用、路径、消耗与余量。
6. 服务空间建立、位移、接触、反制和结果的动作摄影。
7. 与可见脚步、衣料、武器、能量、接触和环境反馈同步的声音。

不得用“更刺激”作为新增能力、伤害、破坏、人数、特效或剧情结果的理由。

## 嵌入 V4 Segment 的步骤

### 1. 建立内部动作状态

为目标 Segment 临时记录参战者起点、朝向、优势距离、既有武器/能量、场景障碍、既定结束位置与既定结果。该记录用于推理和 QA，不新增到成品字段，也不要求创建额外文件。

### 2. 在既定时间内编排动作闭环

将动作组织为“发起 → 接触/格挡/落空 → 回应 → 位移 → 下一状态”。闭环数量由可读性和原动作密度决定，不套用 vendored 模块的默认三方案、默认交锋数、默认镜头数或标准/极速版追问。

首次编写 Segment 时，镜头数仍由核心流程的构图、说话重点、反应、动作阶段、揭示、空间重定向或转场决定。修改已批准 Segment 时，不因调用动作模块自行增删镜头；确需改镜头结构时由核心流程判断，并确保 Segment 数量和时长不变。

### 3. 回填六字段

- `主体`：当前可见角色/物体、相对位置、朝向和必要状态。
- `动作`：完整攻防因果、接触结果、受力、位移、武器/能量及下一拍接口。
- `运镜`：景别、机位、速度、方向、跟随对象和单一主要职责；维持轴线和屏幕方向。
- `风格`：只写该镜必要的视觉风格、光效和非图形化强度，不新增能力。
- `对白/旁白`：保留核心流程确定的对白与说话人；动作模块不得重写。
- `声音与同步`：只写有可见来源、按动作顺序发生的同步声；持续声场留在段级声音基线。

禁止增加“动作设计”“站位”“受力”“武器状态”等第七字段。稳定信息按核心流程放在段级基线，不逐镜复制。

### 4. 保持时间数学

动作密度必须适配既定 Segment 时长，而不是延长 Segment。每镜时长以对白朗读、动作完成、位移距离、镜头路径和声效余韵为依据；最终逐镜时长之和必须精确等于该 Segment 时长。

### 5. 增量 QA

除核心 V4 QA 外，对动作 Segment 只增查：

- 每次攻击是否有目标、接触结果、回应、位移和下一拍接口；
- 人物左右关系、朝向、距离、速度、动作轴是否跨镜连续；
- 武器数量、持握、弹药、能量来源/路径/余量是否连续；
- 受力方向是否与身体位移和环境反馈一致；
- 动作镜头是否看清空间、接触或结果，而非用运镜遮挡动作；
- 动作声音是否有画面来源、顺序一致，且没有覆盖对白；
- 是否误改剧情、胜负、对白、能力、Segment 数量/时长或六字段格式。

发现失败生成结果时，读取 `vendor/fight-prompt-director/references/diagnostics.md`，但每轮仍只按核心流程允许的范围做增量修复。

## Vendored 参考的读取路由

- 需要选择双人攻防、远程能量、一对多、人兽、演武等动作骨架时，读取 `vendor/fight-prompt-director/references/fight-design.md`；只借鉴通用结构，不复制示例角色、场景或动作链。
- 需要确定动作机位、镜头职责、轴线或跨镜状态时，读取 `vendor/fight-prompt-director/references/camera-guide.md`。
- 用户提供失败结果或要求动作专项验收时，读取 `vendor/fight-prompt-director/references/diagnostics.md`。

引用相对路径时，以 V5 Skill 根目录为基准。vendored 模块中的独立成品格式、三方案输出、默认参数和补问逻辑一律由本适配层覆盖。
