# 每日运行 Skill

## 触发条件

每天开始、结束，或用户说“整理今天内容”“沉淀今天内容”时触发。

## 输入

当天的碎片、对话、资料、任务、问题和工作记录。

补充输入源：

- 自动化记忆或上次运行摘要
- `00_Inbox_碎片收集` 整个目录，而不只是一页
- 与当天碎片相关的项目、决策、Skill、自动化候选和最近复盘

## 处理步骤

1. 先读取自动化记忆，确认上次已经处理到哪里，避免重复分流。
2. 扫描整个 `00_Inbox_碎片收集` 目录，记录上次运行后新增或更新的页面、附件和收集入口。
3. 读取当日核心来源，至少包括 `今日收集.md`，必要时补读相关入口页、项目笔记和最近 triage draft。
4. 把内容分类为 Inbox、项目、决策、Skill、自动化候选、原则或复盘，并明确“保留原处”还是“升级沉淀”。
5. 按下面三个分支输出：
   - 有新原始输入：做正常分流，写清去向和后续动作。
   - 无新文本，但有既有项目资产或外部工具线索待跟进：做轻量复核，把后续动作挂到项目层或 review。
   - 完全无新增输入：只记录轻量复核结论，不制造重复笔记。
6. 识别重复出现的主题，判断是否需要补强现有 Skill 检查项，或进入自动化候选观察。
7. 追加 dated triage draft 到 `07_Reviews_复盘`。
8. 最后更新自动化记忆，记录本轮结论、边界样本和下次关注点。

## 输出格式

```text
今日摘要：
今日处理范围：
应写入 Inbox：
应写入项目库：
应写入决策日志：
应更新 Skill：
应进入自动化候选：
应写入复盘：
今日行动项：
明天最小下一步：
```

## 检查标准

- 每日流程不超过 10 分钟。
- 先判断是否真的有增量，再决定是否写入。
- 不追求完美分类，先保证系统持续运转。
- 不把未核验的外部链接或工作流猜测写成事实。
- 已分流过的项目资产优先由项目笔记承接，不回流重复写入 Inbox。
- 输出结束前必须补一条下次可直接执行的最小下一步。

## 可自动化方向

第 1 周后，可以用 Codex Automation 定时生成每日整理建议。

更适合的自动化形态：

- 定时读取自动化记忆和 `00_Inbox_碎片收集`
- 自动生成 triage draft
- 由人工确认是否写入项目、决策、Skill 或候选池
