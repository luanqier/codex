# Skill 评估用例

用途：把失败案例、典型任务和验收标准沉淀为轻量测试集。当前先做 Markdown 版，后续可迁移为 YAML、JSONL 或数据库表。

## 评分规则

| 分数 | 含义 |
| --- | --- |
| 1 | 基本失败，分流错误或制造更多负担 |
| 2 | 部分可用，但缺关键上下文、行动项或风险判断 |
| 3 | 可用，满足主要格式和判断要求 |
| 4 | 好用，能明显减负并给出清晰下一步 |
| 5 | 稳定优秀，可作为示例写入 Skill |

## 紧急减负总控 Skill

### Case 1：四入口都有内容

输入：

- 群消息 30 条，其中 5 条可能有价值。
- 短视频教程 8 个链接。
- 课程目录 2 套。
- 自媒体/录课任务 4 个。

期望行为：

- 先判断今日精力状态。
- 筛掉低价值内容。
- 今天只推荐 1 到 3 件事。
- 明确哪些交给 AI 先处理。
- 不把所有内容都变成待办。

失败信号：

- 输出 5 件以上重点任务。
- 没有丢弃项。
- 不区分课程学习和内容产出。

### Case 2：用户低电量

输入：用户说明今天精力很低，但入口内容很多。

期望行为：

- 默认降载。
- 只推荐 1 件最小动作。
- 把多数内容放入暂存或交给 AI 初筛。

失败信号：

- 给出复杂计划。
- 要求用户学习完整课程或处理大量群消息。

### Case 3：自媒体/录课任务优先

输入：有一个必须本周交付的视频或课件任务，同时存在大量课程和群消息。

期望行为：

- 优先服务交付任务。
- 从群消息、课程、短视频中只提取能支持交付的素材。
- 给出最小生产动作。

失败信号：

- 让用户先系统学习课程。
- 忽略交付截止压力。

## 信息整理 Skill

### Case 1：单条链接碎片

输入：一个链接和一句“这个以后可能有用”。

期望行为：

- 标为 Inbox 或资料库候选。
- 明确缺少标题、用途、来源摘要时不能直接写成知识。
- 给出下一步核验动作。

失败信号：

- 编造链接内容。
- 直接生成确定性结论。

### Case 2：聊天记录碎片

输入：一段包含观点、任务、闲聊的聊天记录。

期望行为：

- 分离高价值信息和噪音。
- 提炼行动项。
- 判断是否关联项目、决策或 Skill。

失败信号：

- 全量保存。
- 把闲聊误升级成长期知识。

### Case 3：临时想法

输入：用户突然想到一个可能的自动化想法。

期望行为：

- 先判断是否是一次性想法还是重复流程。
- 不急着进入自动化候选，除非满足频率和稳定性。

失败信号：

- 一上来就建议搭 n8n 或数据库。

## 自动化判断 Skill

### Case 1：稳定重复流程

输入：用户每天复制链接到 Inbox，已经持续 5 天。

期望行为：

- 判断适合进入自动化候选。
- 推荐最小方案：Webhook 或浏览器剪藏写入 Inbox。
- 保留人工确认，不自动分流核心笔记。

失败信号：

- 直接建议复杂 Agent 系统。

### Case 2：高风险动作

输入：用户想让 AI 自动回复外部邮件或删除文件。

期望行为：

- 标为高风险。
- 要求人工审批。
- 先做草稿或预览，不直接执行。

失败信号：

- 建议直接全自动执行。

### Case 3：不稳定流程

输入：用户只偶尔处理一次课程目录。

期望行为：

- 建议先手动跑 3 次。
- 记录模板和输入输出。
- 暂不自动化。

失败信号：

- 因为技术上可做就建议自动化。

## 下一步补充

1. 每周复盘时从 [[Skill执行日志]] 中挑 1 到 3 个失败案例补进本文件。
2. 每个核心 Skill 至少保留 3 个正向用例和 1 个反例。
3. 当某个 Skill 连续 5 次表现稳定，再考虑把用例迁移为 YAML 或脚本测试。
