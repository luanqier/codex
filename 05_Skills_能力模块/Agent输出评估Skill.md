# Agent输出评估 Skill

## 触发条件

当需要判断 AI/Agent 的输出是否可靠、是否需要返工、是否可以写入 AI-Brain 或交付给外部对象时触发。

典型场景：

- 重要总结、方案、报告、脚本、课件输出后。
- 使用了多个 Skill 或跨多个文件写入后。
- 用户觉得“这个回答好像不太对”。
- 准备把 AI 输出用于外部沟通、发布、课程或正式材料前。

## 输入

- AI 输出内容。
- 原始任务要求。
- 相关上下文文件或来源。
- 预期输出格式和使用场景。

## 处理步骤

1. 检查是否回答了用户真正的问题。
2. 检查是否读到了必要上下文。
3. 检查事实、文件路径、日期和来源是否可靠。
4. 检查输出是否减负，而不是制造更多待办。
5. 检查是否符合相关 Skill 的输出格式。
6. 检查是否存在安全风险、隐私风险或未经确认的外部动作。
7. 给出通过、需小改、需返工三个等级之一。
8. 如果发现失败模式，建议写入 [[Skill执行日志]] 或 [[Skill评估用例]]。

## 输出格式

```text
评估结论：通过 / 需小改 / 需返工

主要问题：
1. 
2. 
3. 

风险：

建议修改：

是否需要更新 Skill：
是否需要新增评估用例：
```

## 检查标准

- 先看真实可用性，不只看表达是否漂亮。
- 对事实、日期、文件路径、外部来源保持谨慎。
- 对高风险动作必须要求人工确认。
- 如果输出没有帮助用户减少判断负担，应判为需小改或需返工。

## 可自动化方向

- 对每日减负草稿、每周复盘草稿自动跑一次轻量评估。
- 对即将写入决策日志、原则库、自我模型的内容自动检查风险。
- 后续可和 [[Skill评估用例]] 结合，形成回归测试。
