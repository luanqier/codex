## 3. 重要架构判断

### Dify 和 n8n 不是大脑

Dify 和 n8n 更适合做执行层、工作流层和工具连接层，不适合作为完整大脑。

真正的大脑层应该包含：

- 自我模型
- 目标系统
- 决策引擎
- 原则库
- 决策日志
- Skill 进化机制
- 复盘机制

### Codex 和 Claude Code 的判断

当前推荐：

```text
Codex = 主工作台
Claude Code = 复杂代码项目副手/审查员，可选
```

Codex 更适合当前系统，因为它能处理：文件、文档、代码、Skill、自动化配置、长期项目维护。

### n8n 和 Hermes 的判断

n8n 和 Hermes 不是同类工具。

```text
n8n = 稳定自动化管道、Webhook、定时器、API连接器
Hermes = 常驻智能体、长期陪跑、主动提醒、浏览器半自动操作
```

按照当前需求，Codex + n8n 能替代 Hermes 的 70% 到 85%，但不能完全替代 Hermes 的常驻陪跑和多平台即时交互体验。

当前建议：

```text
先用 Codex + n8n 做满 80%
再判断是否需要 Hermes 补常驻智能体能力
```

## 12. 信息分流规则

- 一次性想法、链接、资料、图片、视频、临时问题 -> Inbox

- Skill 使用 5 次以上，建议考虑自动化。
- 重要选择必须进入决策日志。
- 自动化前先手动跑通。

## 13. n8n 如何接入当前系统

n8n 不替代 AI-Brain 或 Codex。

分工：

```text
AI-Brain = 长期记忆和规则中心
Codex = 深度执行、系统维护、文件处理、Skill升级
n8n = 外部采集、定时触发、跨工具执行
```

n8n 最适合当前先做：

```text
Webhook -> 判断类型 -> 写入 AI-Brain 快速收集/四个入口
```

第一批 n8n workflow：

1. 统一快速收集入口。
2. B站收藏夹定时扫描。
3. 群消息半自动收集。
4. 短视频链接收集。
5. 课程目录/网盘资料收集。
6. 每日减负草稿。

n8n 当前不应该先做大脑，只做“信息怎么进来”和“稳定重复流程怎么跑”。

## 14. B站和视频号判断

B站收藏夹：可以较自动化。

```text
B站收藏夹 -> RSSHub / API / yt-dlp / n8n -> 写入短视频教程入口 -> AI 判断值不值得看
```

视频号：不建议一开始全自动批量读取。

更稳方案：

```text
视频号链接 / 截图 OCR / 手动摘录 -> n8n Webhook 或 Codex -> 短视频教程入口 -> AI 判断
```

原因：视频号较封闭，个人收藏全自动读取不稳定，可能有账号、安全、隐私和维护风险。

## 15. 群消息自动监测判断

微信群：不建议做全自动官方监听。

更稳方案：

```text
复制群消息 / 截图 OCR -> n8n Webhook -> 群消息收集入口 -> 群消息提炼 Skill
```

飞书、钉钉、企业微信、Telegram、Slack 等：可以通过官方 Bot/Webhook/API 更稳定自动监听。
